# 产品经理试玩结论

口径：墨水屏《夜市置业》（480×800 1bpp）。依据本机 Node 真宿主 PM 1–34 自动试玩去重帧，**以 PNG 实见为准**。豆包视觉 `doubao-seed-2-1-lite-260915`（`maifangji/playtest/vision-findings.json`）仅作对照，不采信其把「按钮可见」标成 P0、以及漏标帮助页黑底黑字的结论。本文件只给产品结论，不改 `index.lua`、不改素材。

## 总观

这是一款「52 周内倒买倒卖、凑钱买房」的夜市经营游戏。目标一句话能讲清，帮助文案本身也基本把核心规则讲完了：房价每周涨、货摊低买高卖、货仓有容量、健康/名声有惩罚、三个市场过一周、银行/医院/售楼部/中介各管一件事。

产品真正的问题不在规则，而在**信息层级和引导可见性**：

1. **帮助能点完，但「离开」在前 8 步等于不存在。** 全屏黑 mask 把脚按钮吞进黑底；未选中的「离开」是黑字黑底。新手只看得见被选中的「下一步」。最后一步焦点落到「离开」才突然看见出口，同时「下一步」消失。
2. **主界面把「看货名、看价格」这个核心动作做成了插画和表格抢同一层。** 货仓线稿从顶栏下方铺到状态栏，锯齿分界线斜穿价格列，长货名被柜子切开。玩家要做的第一件事是比价，画面却先给了一张摊位速写。
3. **弹层盖住现金/存款，底栏还露在外面。** 买货、存钱、看病、扩仓、结束游戏时，决策依据被挡，底下三行按钮仍可被当成可点目标。
4. **底栏三行按钮是故意叠的**（市场 / 银行医院售楼中介 / 帮助历程），在 480 高的屏上能塞下功能，但焦点、热区和「现在能点什么」都糊成一块。这不是偶然 bug，是用密度换层级。
5. **售楼部是赢面场景，文案却挤成一团**，顶栏还有一个与底栏「离开」重复的「返回」。

一句话：规则教得出来，**屏幕上该被看见的字经常看不见，该让位的装饰不肯让位。** 新手过帮助靠「一直点右下角那颗白字」；进主界面后，比价和钱数这两件最重要的事，经常被插画和弹层压住。

## P0 / P1 / P2

### P0

#### PM-P0-01 帮助页 mask 把脚按钮吞进黑底；未选中的「离开」黑字黑底不可见

- **现象：** 帮助 9 步使用全屏黑遮罩讲规则。脚部双按钮仍在原位，但未获焦点的「离开」与黑底同色，肉眼等于没有。第 1–8 步只能看见右下角选中态白字「下一步」；第 9 步焦点改到「离开」，左下才出现白字「离开」，「下一步」同时消失。
- **证据路径：**
  - `maifangji/playtest/unique/007-pm-help-1.png`（只见「下一步」，不见「离开」）
  - `maifangji/playtest/unique/011-pm-help-5.png`（市场三键被点亮，脚部仍只见「下一步」）
  - `maifangji/playtest/unique/012-pm-help-6.png`、`013-pm-help-7.png`、`014-pm-help-8.png`（同上，只有「下一步」）
  - `maifangji/playtest/unique/015-pm-help-9.png`（因焦点在「离开」才看得见；无「下一步」）
- **对玩家 / 信息层级的影响：** 新手在墨水屏上的第一课是「屏幕上没有的东西就不存在」。他们会以为帮助只能向前、不能退出；走到最后一页又找不到已经用了八次的「下一步」。引导完成率靠惯性，跳过率和「我卡在教程里了」的误判同时变高。帮助本应降低门槛，现在把唯一出口藏起来。
- **建议改法：**
  1. 帮助脚按钮不要画进黑 mask：白底黑字描边，或黑底白字成对出现，「下一步 / 离开」始终同时可见。
  2. 未选中态至少保留白框或反白描边，禁止黑字落在黑底。
  3. 最后一步不要偷换 CTA：保留「下一步」灰态或改成「完成」，「离开」始终在同一位置。
- **验收标准：** 帮助 1–9 每一帧上，「离开」与「下一步」（或最后一步的「完成」）无需猜测即可辨认；把焦点从「下一步」挪到「离开」时，另一个按钮仍在、只是失焦而不是消失。抽测 Classic 焦点走完 9 步与中途按「离开」都能回到主界面。

#### PM-P0-02 主界面货仓插画与货名/价格抢层，核心比价信息不可读

- **现象：** 摊位/货架线稿从约 y=60 铺到现金状态栏。市场表、价格列、出租屋表叠在插画和中间锯齿分界线上。长货名「阅星瞳X4P」被柜台切开；对局中「新风滤芯」整行压在玻璃柜上，「老头乐车」被切到状态栏边缘。空局时表头「货物 / 价格 / 买入价数量」已经和吊灯、锯齿线缠在一起。
- **证据路径：**
  - `maifangji/playtest/unique/006-pm-main-empty.png`（空仓：插画铺满中区，锯齿线贯穿两栏）
  - `maifangji/playtest/unique/008-pm-help-2.png`（「阅星瞳X4P」被货箱轮廓切断）
  - `maifangji/playtest/unique/016-pm-playing.png`（「新风滤芯」叠在柜上，价格列被锯齿线切开，「老头乐车」贴底被切）
- **对玩家 / 信息层级的影响：** 本游戏的核心循环是「看价 → 判断区间 → 买/卖」。货名和价格应是第一视觉层级，插画应是背景。现在装饰在上、数据在下，等于让玩家在速写稿里找数字。墨水屏没有灰度层次可补救，叠层就是丢字。长货名进一步暴露列宽不够。帮助第 2 步还在教「点货物可以买入」，被切开的那一行正好是反例。
- **建议改法：**
  1. 插画限制在表格下方的装饰带，或整体下移/裁切，禁止穿过货名行与价格数字。
  2. 市场 | 出租屋用直线或留白分栏，锯齿撕裂线若保留，只能走两表之间的空隙，不得穿过数字。
  3. 货名列预留 6–8 个汉字宽度，超长名用两行或缩短用名（「阅星瞳X4P」这类型号名尤其要收）。
- **验收标准：** 任意 5 条在售货物的名称与价格，在空仓和对局两帧上都能完整阅读，不与插画轮廓、锯齿线、状态栏相交。抽测含「阅星瞳X4P」「新风滤芯」「老头乐车」在列的帧。

### P1

#### PM-P1-01 买卖/银行/医院/中介/退出弹层盖住现金·存款栏，底栏仍露出

- **现象：** 白色弹层停在屏幕中下部，把「现金 / 存款」黑条挡住（只剩左侧「现」「存」残字），同时底栏三行按钮从弹层底下露出来。买货时玩家要看还剩多少钱；银行弹层时玩家要看现金和存款；退出确认时底下「结束游戏」和弹层「结束」同时在场。
- **证据路径：**
  - `maifangji/playtest/unique/017-pm-buy-overlay.png`（购买数量层压住现金/存款；快捷数量 5/2/1 叠在市场键上）
  - `maifangji/playtest/unique/018-pm-bank.png`（存钱/取钱/离开，状态栏被挡，底栏仍露）
  - `maifangji/playtest/unique/019-pm-hospital.png`（看病/离开，同上）
  - `maifangji/playtest/unique/020-pm-agency.png`（扩仓成交/离开，同上）
  - `maifangji/playtest/unique/024-pm-quit-overlay.png`（结束/取消，现金残字 + 底栏「结束游戏」双焦点）
- **对玩家 / 信息层级的影响：** 弹层出现时，信息优先级应是「当前决策 + 做决策需要的数字」。现金/存款是买货和存取的硬约束，被盖住就变成心算或靠弹层里那句「最多可以购买 5 个」补救——银行、中介没有同等补救。底栏不隐藏，等于告诉玩家「下面那些键还活着」，误触和市场键抢焦点的风险上升。退出确认尤其危险：弹层「结束」和底栏「结束游戏」语义重复。
- **建议改法：**
  1. 弹层上移或减高，给现金/存款条留出完整一行；或把现金、存款、货仓余量抄进弹层页眉。
  2. 弹层打开时隐藏或压暗底栏，只保留弹层内按钮可走焦点。
  3. 退出确认用独立模态，文案与底栏「结束游戏」区分（例如「确认结束本局？」），底栏不可点。
- **验收标准：** 打开买/卖、银行、医院、中介、结束确认时，现金与存款数字完整可见；底栏市场/银行/帮助键不可见或明确不可点；画面上只出现一套「确认/离开」焦点。

#### PM-P1-02 售楼部房源简介挤叠；首套房名被黑块吃掉；顶栏「返回」与底栏「离开」重复

- **现象：** 售楼部是 52 周目标的兑现页。第一套房源名称区被右上黑块盖住，只剩「售价：40.0万」；简介「30平米的临街单间 / 收摊后两个人住也够用」行距崩掉，字叠字。第二套「巷口老屋」标题可读，简介「巷口的80平米老屋，虽旧，但进出方便」同样挤叠。顶栏已有「返回」，底栏又有「离开」。
- **证据路径：** `maifangji/playtest/unique/021-pm-houses.png`
- **对玩家 / 信息层级的影响：** 玩家攒了 52 周进来看房，第一眼看不到房名、看不清卖点，只看见一个价。买房决策变成「看数字、猜户型」。顶底双出口在墨水屏上会让人犹豫「返回是上一页还是退出售楼部」。历程表（见下）也是顶「返回」+ 底「离开」，说明这是模板问题，不是单页疏忽。
- **建议改法：**
  1. 房名、售价、简介分成三行，行距至少一字高，禁止多行正文抢同一 y。
  2. 去掉右上无意义黑块，或把它改成不遮标题的装饰。
  3. 全屏子页只留一个出口：要么顶栏「返回」，要么底栏「离开」，不要两个。
- **验收标准：** 售楼部每一套房的名称、售价、简介均可连续阅读、无叠字、无遮挡；页面上只有一个离开/返回入口。抽测至少两套房源卡片。

#### PM-P1-03 帮助第 3 步把「30/100」讲成剩余空位，实况 HUD 却是 70/100；货名与买入价粘连

- **现象：** 帮助文案写「30/100 表示最多存放 100 件，目前还剩 30 个空位」，右侧出租屋标题是「出租屋 (70/100)」——按占用计数是已装 70，剩余 30，和文案举的「30/100」不是同一套读法。列表里「老头乐车15023」「金豆金条2065」货名与买入价拼成一串，「买入价数量」表头无分隔。
- **证据路径：** `maifangji/playtest/unique/009-pm-help-3.png`
- **对玩家 / 信息层级的影响：** 货仓容量是中盘资源管理的关键指标。教程用一个示例分数，实况 HUD 用另一个分数，还把「已占用 / 上限」讲成「剩余 / 上限」。新手会按字面去对，对不上就不再信 HUD。货名和价格粘连则让「买入价」列失去独立层级。
- **建议改法：** 帮助举例必须等于当前 HUD；统一口径为「已占用/上限」（70/100 = 已放 70，还能放 30），文案跟读。货名与买入价分列，表头写成「买入价 / 数量」。
- **验收标准：** 帮助第 3 步屏幕内，文案中的分数与「出租屋 (x/y)」一致；任意货仓行都能分清货名、买入价、数量三列。

#### PM-P1-04 医院弹层「看病」键被斜线切开

- **现象：** 「看病」白按钮上有一条从市场锯齿分界线延伸过来的斜线，穿过「看病」两字并伸出按钮边界。焦点在「离开」上，这条线格外抢眼。
- **证据路径：** `maifangji/playtest/unique/019-pm-hospital.png`
- **对玩家 / 信息层级的影响：** 医院是「健康低于 95 会摊倒」的对策入口。按钮被划开，轻则像坏点，重则让人以为该键不可用。弹层没有把下层装饰裁干净，层级再次穿帮。
- **建议改法：** 弹层不透明底板盖住锯齿线；按钮内部禁止穿过下层分界线。
- **验收标准：** 「看病」「离开」两键内部无异线、无插画穿透；文案「身体好好的来医院干啥……」完整可读。

### P2

#### PM-P2-01 底栏三行按钮故意重叠（市场 / 银行医院 / 帮助）

- **现象：** 第一行三个市场、第二行银行/医院/售楼部/中介、第三行帮助/开始(结束)游戏/历程表，行与行在垂直方向咬合，图标压在上行文字区。空局与对局同构。这是在 800 高里硬塞九个入口的设计选择，不是渲染事故。
- **证据路径：** `maifangji/playtest/unique/006-pm-main-empty.png`、`maifangji/playtest/unique/016-pm-playing.png`
- **对玩家 / 信息层级的影响：** 功能都能看见，但「哪一行是现在的选择」要靠反色硬认。帮助第 5 步只点亮三个市场、第 6–9 步每次只露出一颗键，说明作者也知道整组底栏不能一起讲。密度换来的是误触和「帮助键藏在市场下面」的发现成本。
- **建议改法：** 不强制拆成分页，但至少：选中行整体抬高/留 4px 白缝；未选中行不要让图标压进另一行的标题。若改动成本可接受，把「帮助 / 历程 / 结束」收到溢出菜单，主底栏只留市场 + 四处地点。
- **验收标准：** 不要求改玩法。验收时，三行标题均不被邻行图标切字；焦点在「帮助」「银行」「二手市场」时，玩家能在 1 秒内指出当前键。若保持重叠，需在帮助第 5 步明确说「下面还有两行」。

#### PM-P2-02 开局空态健康/名声为 0，像一局已经打残的号

- **现象：** 未点「开始游戏」时，顶栏「房价：— / 时间：0/52周」合理，但「健康：0 / 名声：0」与对局中的 100/100 不一致。帮助第 4 步展示的是健康 96、名声 98，和空主界面也不一致。
- **证据路径：** `maifangji/playtest/unique/006-pm-main-empty.png`（对照 `016-pm-playing.png`、`010-pm-help-4.png`）
- **对玩家 / 信息层级的影响：** 状态栏是信任区。开局就看到健康 0，会让人以为「还没开始就已经摊倒」，或以为 0 是空数据占位。和帮助讲的「低于 95 会累倒」直接冲突。
- **建议改法：** 未开局不显示 0，改「—」或直接给开局值 100；帮助演示帧与开局 HUD 使用同一套数字。
- **验收标准：** 进入主界面未开局时，健康/名声要么空白占位，要么等于开局值；不得出现 0。

#### PM-P2-03 历程表可读，但同样是顶「返回」+ 底「离开」

- **现象：** 「我的置业记录」表头「房型 / 首次购买时间 / 成功次数」清晰，十行房型完整。焦点在底栏「离开」。顶栏另有「返回」。这页信息层级是全游戏最好的一档，问题只剩双出口模板。
- **证据路径：** `maifangji/playtest/unique/022-pm-records.png`
- **对玩家 / 信息层级的影响：** 不会挡理解，但和售楼部同一套「两个离开」。Classic 用户会问焦点该走哪颗。
- **建议改法：** 与售楼部统一为一个出口。历程表可作改完后的对照页：证明「白底表格 + 单行高 + 不叠插画」在这块屏上是可读的。
- **验收标准：** 历程表保持当前可读性；页面仅保留一个离开/返回。

#### PM-P2-04 帮助第 7 步医院图标顶部被裁切

- **现象：** 点亮「医院」时，图标上沿缺一块，像从底栏叠层里抠出来的。
- **证据路径：** `maifangji/playtest/unique/013-pm-help-7.png`
- **对玩家 / 信息层级的影响：** 不影响把教程点完，但强化「底栏是从别的层挖出来的」印象，和 P0-01 的 mask 是同一类层级债。
- **建议改法：** 聚光展示时给按钮完整白底，不要带上行的残片。
- **验收标准：** 帮助 6–9 步被点亮的地点键四边完整、不带邻行残画。

走完路径：前 8 步一直点右下角白字「下一步」，第 9 步改点左下角「离开」。自动试玩能跑通，是因为脚本知道按钮还在原坐标，不依赖像素对比度。

真人新手会遇到的断点：

1. **看不见跳过。** 想离开帮助的人会以为没有出口，只能硬看完 9 页。
2. **最后一页换按钮。** 训练记忆是「右下角下一步」；第 9 页右下角空了，出口跑到左下。墨水屏刷新慢，更容易以为卡死。
3. **内容能教完规则，演示帧却打脸。** 第 2 步货名被插画切；第 3 步容量口径和 HUD 不一致。规则听懂了，对照屏幕会对不上。
4. **第 5 步只露出三个市场，** 与主界面「三行叠按钮」的真实底栏不一致，出教程后仍要自己发现银行/帮助在哪。

产品结论：帮助作为「线性向前的幻灯」可以交卷；作为「可退出、可对照、可建立信息层级」的新手引导，不及格。优先修 PM-P0-01，否则后面所有帮助文案改动都落在一张看不见脚按钮的黑底上。

## 与视觉 JSON 的分歧

对照文件：`maifangji/playtest/vision-findings.json`，模型 `doubao-seed-2-1-lite-260915`，48 图 / 88 条。下列以 PNG 实见为准，**不采信 JSON 的优先级和漏检。**

### 1. JSON 把「按钮可见」标成 P0 —— 否决

- `004-pm-story.png`：「继续按钮为黑底白字可见」「上部文字未被遮挡」被标 P0；「控件无重叠」被标 P1。
- 这是正常、健康的帧。可见性不是缺陷。视觉模型把「我看见了」写成 finding，并给了最高优先级，会污染排期。
- 同类噪声：多处 `vision_call_failed`（`002-pm-story.png`、`012-pm-help-6.png` 等）被记成 P2 缺陷，那是调用失败，不是游戏问题。

### 2. JSON 漏了帮助页黑底黑字 —— 本报告升为 P0

- 对 `007-pm-help-1.png`、`010-pm-help-4.png`、`011-pm-help-5.png`、`015-pm-help-9.png` **没有一条**关于「离开」不可见的 finding。
- `004-pm-story.png` 的 evidence 还写「未出现黑底黑字或白底白字的不可见情况」，等于用故事页的反例，把帮助页的真问题排除掉了。
- 人眼：help-1 / help-5 只见「下一步」；help-9 只因焦点在「离开」才看见。这是本报告 PM-P0-01。

### 3. JSON 把「按钮在」当成对比度问题，没问「钱还看得见吗」

- `017-pm-buy-overlay.png`：JSON 强调底栏文字对比度和弹层盖住货架。实见更关键的是 **现金/存款被盖住**，底栏还露着。买货决策缺钱数。
- `018-pm-bank.png`：JSON 写到现金/存款被挡、底栏被挡，方向对，但标 P1 且没上升到「弹层打开时状态栏是决策依据」。本报告收成 PM-P1-01。
- `024-pm-quit-overlay.png`：JSON 抓锯齿裂纹和底栏被挡；没提弹层「结束」与底栏「结束游戏」双 CTA。

### 4. 锯齿分界线：JSON 当「裂纹缺陷」，人眼当「设计线穿字」

- JSON 对 `006`、`016`、`024` 等多帧把中间撕裂线写成损坏/裂纹。
- 实见：这是市场 | 出租屋的风格化分界，**线本身可以留**，问题是它穿过价格数字和表头。本报告归进 PM-P0-02 的「装饰抢数据」，不建议当素材破损去修。

### 5. 底栏三行重叠：JSON 当 bug，产品当已知取舍

- JSON 在多帧（含非 PM 的 gamer/engineer 帧）把图标压字、按钮不齐写成 P1/P2 overlap。
- 实见：`006-pm-main-empty.png`、`016-pm-playing.png` 结构相同，是故意叠三行。本报告标 PM-P2-01，不进 P0。要改是信息层级优化，不是「修重叠 bug」。

### 6. 售楼部：JSON 看到了挤字，但优先级偏低，且误读黑块

- JSON 对 `021-pm-houses.png`：简介挤叠标 P2，右上黑块标 P1「遮挡房源区域」。
- 实见：黑块直接吃掉第一套房名；简介是字叠字，不是略挤。赢面页的可读性应高于 P2。本报告 PM-P1-02。
- JSON 另写 `020-pm-agency.png`「银行的『行』被裁切」——该帧是中介扩仓弹层，左下「银行」被弹层挡住上沿，不是「行」字被屏幕裁掉。不单列缺陷。

### 7. JSON 说对、且与人眼一致、本报告采纳的部分

- 货名/价格被插画和分界线切断（`008`、`016`）——纳入 PM-P0-02。
- 帮助第 3 步 30/100 与 70/100 口径冲突（`009`）——纳入 PM-P1-03；JSON 标 P2，这里提到 P1，因为教程与 HUD 对不上会毁掉信任。
- 医院图标裁切（`013`）——纳入 PM-P2-04。
- 医院「看病」斜线（`019`）——纳入 PM-P1-04。

### 8. 排期时怎么用 JSON

不要按 JSON 的 88 条 P0/P1 刷缺陷单。先做本文件四条 P0/P1（帮助离开可见、主界面比价可读、弹层让出钱数、售楼部简介与单出口），再处理容量口径和看病键。JSON 里所有「按钮可见」「调用失败」「裂纹=损坏」「底栏故意重叠」一律不进缺陷。
